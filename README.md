# GameZh · 游戏实时翻译悬浮窗

Windows 10/11 x64 便携软件。框选屏幕文字后，程序在本机 OCR 识别，再用用户配置的 OpenAI 兼容文本接口翻译成简体中文，最后显示在独立悬浮字幕窗中。不会注入游戏、修改游戏文件或绕过反作弊。

## 下载后使用

把 `GameZh.exe`、`OcrBridge.exe` 和 `使用说明.md` 保持在同一文件夹，双击 `GameZh.exe`。发布包已自带 .NET 10 运行时，不需要安装 Python、Node.js、.NET SDK 或额外 .NET 10 运行时。主程序约 173 MB，这是单 EXE 自包含发布的体积；OCR 桥接约 6 KB。

首次使用按界面顺序操作：

1. 选择系统已安装的 OCR 语言。程序会列出可用语言，优先显示英语、日语、韩语。若缺少目标语言，请到 Windows **设置 → 时间和语言 → 语言和区域 → 语言选项**安装相应语言和 OCR 功能，再点“刷新语言”。
2. 输入 OpenAI 兼容 API 地址、模型名称和自己的 API Key（本机服务可不填 Key）。可输入完整 `/chat/completions` 地址，也可输入以 `/v1` 结尾的基址。点击“测试连接”，确认真实服务返回译文。在线服务需要联网，并可能产生服务商费用；软件没有内置密钥。
3. 点击“框选区域”，用鼠标选中游戏对白或菜单文字。点击“识别预览”确认截图位置；点击“手动识别”可立即试运行一次。
4. 点击“开始翻译”。字幕窗默认置顶且鼠标穿透。关闭主窗口会缩到系统托盘；托盘菜单可开始/暂停、重新框选、显示/隐藏字幕、打开设置、退出。

默认全局快捷键是 `Ctrl+Shift+F8` 开始/暂停、`Ctrl+Shift+F9` 重新框选、`Ctrl+Shift+F10` **退出鼠标穿透**。可以在主窗口分别改成 F5–F12；冲突时状态栏会提示，托盘菜单仍可操作。退出穿透后可拖动字幕窗和拖动右下角调整大小；宽度、透明度、字号、字体颜色和是否显示原文也可在主窗口调整。

## 实现与数据

- 主程序：.NET 10 LTS、WPF、Windows x64 自包含单文件。OCR 组件：Windows 自带 `Windows.Media.Ocr`，以常驻小进程调用。截图、OCR 都在本机处理；仅识别出的文本及少量上一句上下文发送到配置的翻译接口。
- 翻译请求使用 `POST /chat/completions`、`model`、`messages`、`temperature` 和 `max_tokens`，读取 `choices[0].message.content`。接口兼容程度由服务提供方决定。[聊天补全接口参考](https://platform.openai.com/docs/api-reference/chat/create)
- 相同画面跳过 OCR，相同文字使用最多 256 条翻译缓存；文字变化短暂等待稳定，同一时间不堆积识别任务。新文字出现或暂停时取消旧请求，并用版本号阻止旧译文覆盖新译文。HTTP 408、429、5xx、超时及连接故障有限重试；401/403 不自动重试。
- API Key 通过 Windows 当前用户的 DPAPI 加密保存在 `%APPDATA%\GameZh\settings.json`。日志在同目录，轮转上限约 3 MB；默认不记录密钥、截图和完整文字。配置损坏时备份旧文件并恢复默认设置。
- 独占全屏、受保护画面或特殊渲染环境可能无法采集或显示字幕。优先使用窗口化、无边框全屏。重叠时截图前临时隐藏字幕窗，避免把自己的字幕再次识别。

## 从源码构建

在 Windows x64 构建机安装 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)，然后在本目录运行 PowerShell 脚本：

```powershell
.\publish.ps1
```

发布包输出在 `dist\GameZh\`。脚本还会用 Windows .NET Framework 编译器生成 OCR 桥接程序。源码在 `app\` 和 `ocr\`，测试在 `tests\`。目标电脑运行发布包不需要 SDK。构建机若有本地 `packages\`，脚本优先使用这些 NuGet 包；否则使用正常网络还原。
